# ふたりの信州暮らし帳

同棲の家計ダッシュボード。長野県（松本・塩尻・安曇野）でふたり暮らしを始めるための
お金の計画と、住み始めてからの家計簿を、2人で共有して使うためのページ。

**公開URL：** https://harutong08.github.io/futari-kurashicho/

`index.html` の1ファイルで動く（外部から読むのは Google Fonts だけ）。ビルドは不要。
スマホの「ホーム画面に追加」でアプリのように使える（`manifest.webmanifest`）。

## 4つの画面

| タブ | 中身 |
|---|---|
| ホーム | **やることリスト**、生活費の合計と状態、手取りの編集、内訳の円グラフ、月別の光熱費、今月の家計簿 |
| 初期費用と貯金 | 初期費用のチェックリスト（**項目ごとにメモ**）、毎月の貯金額、ボーナス、貯金の見通し、月ごとのスケジュール表 |
| 毎月の予算 | 名前・収入・エリア、分担方法3つの比較、予算項目の増減、**GitHubとの同期**、バックアップ |
| 家計簿 | レシートの写真からの読み取り、支出の記録（払った人＝2人のどちらか／共通口座）、予算と実績、月末の精算額 |
| チャット | 2人のやりとり。未読には印が付く。合言葉をかけていれば中身も暗号化される |

## 保存のしくみ

入力した内容は、このリポジトリの2つのファイルに書き込まれる。

- `data/settings.json` — 名前・収入・予算・初期費用・貯金計画（1ファイル）
- `data/expenses.json` — 支出の記録（配列）
- `data/chat.json` — チャットの発言（配列・直近500件だけ残す）
- `data/todos.json` — やることリスト（配列）

書き込み先は main ブランチ。ファイルはアプリが自動で作るので、あらかじめ置いておく必要はない。
読み込みは10秒ごと（トークンなしの閲覧は5分ごと）と、タブに戻ったときにも走る。
GitHubには「変わったら教えてくれる」仕組みがないので、こちらから聞きに行く方式しか取れない。
そのためどうしても最大10秒の遅れが出る。間隔は `POLL_MS` で変えられる。
回数制限はトークンありで1時間5,000回。10秒間隔だと1台あたり720回/時なので、2台でも3割ほど。

状態は3つある。画面右上の表示で分かる。

| 表示 | いつ | 保存先 |
|---|---|---|
| この端末だけに保存 | トークンがなく、GitHub側にもまだデータがない | ブラウザ（localStorage） |
| 見るだけ | トークンがないが、GitHub側にデータがある | 保存しない（入力しても消える） |
| 2人で同期中 | トークンがある | GitHub（＋ブラウザにも控え） |

同時に書き換えたときは、設定は後から保存した側が残り、家計簿とチャットは**両方の記録を
突き合わせて**残す（消した記録が相手の画面から復活しないよう、消したidを覚えている）。

**まだ送れていない変更があるうちは、相手の内容で上書きしない**（`settingsDirty`）。
これが無いと、項目を足した直後（保存までの待ち時間中）に相手の読み込みが走ったときに、
足したばかりの欄が消える。項目の追加・削除など形が変わる操作は0.25秒で送る
（文字を打っているときは0.9秒待ってからまとめて送る）。

チャットはどちらの発言か分けるため、端末ごとに「自分はどちらか」を一度だけ選ぶ
（`futari.me`。チャット画面の「切り替え」で変えられる）。発言は送った瞬間に保存へ向かうので、
相手には最大10秒ほどで届く。消せるのは自分の発言だけ。

## つなぎ方（トークンの作り方）

1. GitHub の **Settings → Developer settings → Personal access tokens → Fine-grained tokens**
2. **Generate new token**。Repository access で **`harutong08/futari-kurashicho` だけ** を選ぶ
3. Permissions の **Contents** を **Read and write** にする（他は触らない）
4. できた `github_pat_…` をコピーし、サイトの「毎月の予算」タブ →「2人で同期する」に貼って**つなぐ**

2人で同じトークンを使ってよい。トークンは各自のブラウザ（localStorage）にだけ入り、
リポジトリにもページのHTMLにも書き込まれない。端末をなくしたら、上と同じ画面から取り消す。

### もう1人に渡すとき（招待リンク）

つないだ端末の「2人で同期する」欄に **「相手用の招待リンクをコピー」** が出る。
コピーしたリンク（`…/#t=github_pat_…`）を相手に送れば、相手は開くだけでつながる。
貼り付け作業がいらない。

- トークンは `#` より後ろに置いてある。**この部分はサーバーに送られない**ので、
  GitHub Pages 側のログやリファラには残らない
- 開いた瞬間にアドレス欄から消し、履歴にも残さない。以後はそのブラウザが覚えている
- **リンクを開いた人は誰でも家計を書き換えられる。** 相手に直接送るだけにして、
  SNSや共有アルバムには貼らないこと。広まってしまったら、GitHubでトークンを取り消せば無効になる

## 見た目

**端末の設定に関わらず、いつも白い画面で表示する。** 端末を暗いテーマにしていても変わらない。

- `<html data-theme="light">` を固定で付け、`color-scheme: light` を宣言している
  （入力欄やチェックボックスまで白基調で揃えるため）
- 暗いテーマ用の色指定は、残しておくと事故のもとなので丸ごと外してある。
  `npm test` で「`prefers-color-scheme` が残っていないこと」まで見ている

## アプリとして使う・自動で更新する

スマホの「ホーム画面に追加」で、アドレスバーのないアプリとして開ける。

そのままだとブラウザが古いページを抱え込んで新しい版に変わらないので、`sw.js`
（Service Worker）を置いてある。やっていることは2つだけ。

- **ページ本体は毎回ネットワークを先に見る**（network-first）。つながらないときだけ手元の控えを出すので、
  電波がなくても開ける
- **読み取り部品（`vendor/`）は一度取ったら手元から出す**（cache-first）。6MBを毎回取りに行かないため

新しい版を置くと、開いた瞬間か、アプリに戻ってきたときに気づいて自動で入れ替わる。
入力中・保存中・レシート読み取り中は待ってから切り替えるので、書きかけが消えることはない。
今どの版かは「毎月の予算」タブの同期の欄に出る。

**`sw.js` の `VERSION` と `index.html` の `APP_VERSION` は必ず同じ文字列にすること。**
ズレると更新が掛からなくなるので、`npm test` の先頭で突き合わせている。

> すでにホーム画面に追加してある場合、この仕組みが入る前の版が居座っていることがある。
> **一度だけ**、ブラウザで開いて強制再読み込み（Ctrl+Shift+R／タブを閉じて開き直す）すると、
> 以後は自動になる。

## やることリスト

ホームのいちばん上（生活費の金額より前）。引越しまでの段取りを2人で共有するためのもの。

- 本文と、任意の期限。チェックすると打ち消し線が付いて下へ移る
- 並び順は「終わっていないもの → 期限が近い順 → 追加した順」、終わったものは最後
- 期限の切迫ぐあいで行ごと色が変わる（`dueState`）
  | 状態 | 見た目 |
  |---|---|
  | 期限すぎ | 赤い背景・左が赤い帯・文字も赤 |
  | 3日以内 | 黄色い背景・左が黄色い帯 |
  | まだ先 | 白いまま・左が緑の帯 |
  | 期限なし | 白いまま・左が灰色の帯 |
  | 終わった | 薄くなって打ち消し線 |
- 期限は当日・明日を言葉で出す。期限がなければ「期限なし」と出す
- 見出しの下に件数の内訳（期限すぎ／3日以内／残り／終わった）を色付きで出す
- 誰が足したかの印が付く（チャットで選んだ「自分はどちら」を使う。選んでいなければ無印）
- 残り3件を切ると「よくあるやること」を勧める（内見の予約、退去連絡、住民票の異動など）
- 「終わった分を消す」でまとめて片付く。消したidを覚えているので相手の画面から復活しない

## 初期費用の並べ替え

優先順位を上から並べられるように、項目を動かせる。

- 左の **⠿ をつまむ**とすぐ動かせる。**行の余白を長押し**（0.42秒）しても動かせる
- 文字入力やボタンの上から始めたときは並べ替えにしない。
  長押しの途中で8px以上動いたら取りやめる（画面のスクロールを邪魔しないため）
- **同じまとまりの中だけ**で入れ替わる（契約時・引越し・家具家電…をまたがない）
- 動かしている間は描き直しを止める（つかんでいる行が消えないように）

## 初期費用のメモ

初期費用の各項目に、鉛筆のボタンからメモを書ける。見積もりの比較（「A不動産は1か月、B社は2か月」）や、
「母からもらう」「内見のときに交渉する」といった覚え書きに使う。

- メモは設定ファイル（`data/settings.json`）の各項目の `note` に入る。合言葉があれば暗号化される
- メモがある項目は鉛筆のボタンが緑になるので、一覧のどこに書いたか分かる
- 空にしてボタンを押せば閉じる。メモ欄は書いてあるときだけ表示する（一覧が長くならないように）

## レシートの読み取り

家計簿タブの「**レシートを撮る・選ぶ**」で、レシートの写真から金額・日付・分類・店名を拾って
記録欄に入れる。**そのまま登録はしない**ので、必ず目で確かめてから「記録する」を押す。

- OCRは同梱した [Tesseract.js](https://github.com/naptha/tesseract.js) 5.1.1（`vendor/`）。
  **ブラウザの中だけで動く。写真はどこにも送らないし、保存もしない**
- 初回だけ `vendor/` から約6MB（日本語データ2.4MB＋エンジン3.9MB）を読み込む。
  2回目以降はブラウザが覚えているので速い
- CDNではなくリポジトリに同梱しているのは、外部サービスが落ちても動くようにするためと、
  この構成のままテストで実際に動かして確かめられるようにするため
- 前処理として、長辺1600pxに整え、白黒にして明暗を伸ばしてから読ませている
- 「合計」の行を探して金額を取る。小計・お預り・お釣り・消費税の行は外す。
  見つからなければ ¥ や 円 が付いた数字のうち最大のものを使う
- OCRは `2,178` を `2, 178` のように空白付きで返すことがあるので、
  全角を半角に直し、桁区切りで割れた数字をつなぎ直してから読む（`normText`）
- 日付は西暦・令和・R表記に対応。今日から前2年〜後2日の範囲外なら採らない
- 店名のキーワードから分類を当てる（`RCPT_CAT`）。ツルヤ→食費、ドラッグ→日用品、ENEOS→車 など

**精度は完璧ではない。** 感熱紙の薄いレシート、しわ、斜めからの撮影では読めないことがある。
明るい場所で、レシート全体がまっすぐ入るように撮ると読めることが多い。

## 合言葉（暗号化）

「毎月の予算」タブの「2人で同期する」→「**合言葉をかける**」で、保存する中身を暗号化できる。
このリポジトリは公開なので、かけておくことを勧める。

- 合言葉から PBKDF2(SHA-256・20万回) で鍵を作り、**AES-GCM** で本文を包む。
  どちらもブラウザ標準の WebCrypto で、外部のライブラリもサーバーも使わない
- GitHubに残るのは `{"enc":"aes-gcm","salt":…,"iv":…,"data":…}` という封筒だけ。
  合言葉を知らない人には、金額も名前も店名も読めない
- 塩は合言葉ごとに1つ作って使い回し、IVは保存のたびに新しく作る
- 合言葉は各自のブラウザ（localStorage）にだけ置く。招待リンクには `&k=` として一緒に載る
- 合言葉がかかっている状態で、合言葉を知らない端末が開くと**合言葉の入力画面**になり、
  中身は一切表示されず、書き込みもできない
- **合言葉を忘れると、それまでのデータは誰にも読めない。**（作り直しになる）
- 合言葉をかける・変える・やめるときは、3つのファイルを**まとめて今の合言葉で書き直す**
  （`rekeyAll`）。普通の保存のように「相手のファイルを読んでからすり合わせる」やり方だと、
  古い合言葉で読めないファイルが永久に取り残されるため
- どれか1つが別の合言葉で保存されていても、**残りは普通に使える**。読めないファイルは
  名指しで画面に出て、「この端末の内容で作り直す」か「別の合言葉を入れ直す」を選べる
  （設定ファイルだけは、読めないと全体が合言葉の入力画面になる）

サイト自体は公開なので誰でも開けるが、開いても合言葉なしでは何も見えない。
これが「URLにパスワードをかける」ことの実質的な代わりになっている
（GitHub Pages に本当のパスワード保護は無い）。

## 検索に出さない

2人で使うページなので、検索結果には出ないようにしてある。

- `robots.txt` で全部を対象外にしている
- ページに `noindex, nofollow, noarchive, nosnippet, noimageindex` を付けている

ただし**リポジトリ自体は公開のまま**で、GitHubのプロフィールには並ぶ。
無料のGitHub Pagesは公開リポジトリでしか使えないので、ここは避けられない。
中身（金額・チャット・やること）は合言葉で暗号化してあるので、リポジトリを開かれても読めない。

## 気をつけること

- **このリポジトリは公開**なので、合言葉をかけていない間は、保存した収入・貯金額・支出の記録を
  誰でも見られる。（無料のGitHub Pagesは公開リポジトリでしか使えないため、
  公開URLを持つことと非公開にすることは両立しない。）合言葉をかければ中身は読めなくなる。
- トークンは `Contents: Read and write` を持つ。ブラウザを他人が触れる状態にしない。
- 保存のたびにコミットが1つ増える（`家計：…` というメッセージ）。

## 金額の根拠

すべて松本・塩尻・安曇野の目安。物件が決まったら見積もりの金額に置き換える前提。
光熱費は月ごとの係数で冬に約2倍になる想定（`SEASON`）、エリアごとのガス代・駐車場代は `AREAS`。
家賃7万・手取り20万＋15万を初期値にしてある。

## 同梱しているもの（vendor/）

| ファイル | 中身 | ライセンス |
|---|---|---|
| `tesseract.min.js` / `worker.min.js` | Tesseract.js 5.1.1 | Apache-2.0 |
| `tesseract-core-simd-lstm.wasm.js` | Tesseract本体（WebAssembly・LSTM・SIMD版） | Apache-2.0 |
| `jpn.traineddata` | 日本語の学習データ（tessdata_fast 4.0.0） | Apache-2.0 |

SIMD対応のブラウザが要る（Chrome 91以降、Safari 16.4以降、Firefox 89以降）。
`.gz` ではなく展開したものを置いているのは、GitHub Pages が `.gz` をどう返すかに依存しないため。
転送時の圧縮はサーバー側が自動でやるので、通信量は変わらない。
